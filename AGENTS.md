# AGENTS.md

## Mission

Build nodspice as a live, browser-first circuit design environment. Preserve the separation between the serializable circuit document, SVG interaction layer and Rust numerical engine.

## Required stack

- Bun 1.4 for JavaScript package management, scripts, tests and serving;
- React for application composition;
- native SVG for the editable schematic;
- plain CSS for visual design and animation;
- Rust compiled to WebAssembly for electrical solving;
- TypeScript strict mode.

Do not add a canvas graph framework, a CSS-in-JS runtime, Redux or a second solver in TypeScript without an explicit architecture decision.

## Source-of-truth rules

1. `CircuitDocument` is the persisted editor source of truth.
2. Wires reference component and terminal IDs, never absolute endpoint pixels.
3. SVG paths are derived from terminal positions.
4. Electrical node numbers are derived by `compileCircuit()` and never persisted.
5. Numerical truth comes from the Rust result, not from visual heuristics.
6. The UI may animate a solved vector, but it must not invent voltage/current values.

## Editor invariants

- render wires below components;
- keep a wide invisible hit path separate from the visible wire;
- route from explicit port directions with outward stubs;
- remove duplicate and collinear route points;
- transform pointer coordinates through SVG CTM before drag math;
- zoom around the cursor using a non-passive native wheel listener;
- snap component positions to the grid;
- preserve semantic connectivity while moving components;
- never use colour alone to communicate selection or an error.

## Solver invariants

- validate finite positive physical parameters at the Rust boundary;
- keep current direction conventions documented;
- every new device must have focused unit tests;
- transient state belongs to the device model, not React;
- avoid panics for invalid user circuits; return a typed error;
- numerical convergence status must reach the UI;
- do not claim SPICE compatibility before compatible parsing, analyses and model behaviour exist.

## Change locations

- persistent circuit types: `src/domain/types.ts`;
- component geometry and ports: `src/domain/components.ts`;
- topology compilation: `src/domain/netlist.ts`;
- wire routing: `src/editor/router.ts`;
- SVG gesture handling: `src/editor/CircuitCanvas.tsx`;
- numerical algorithms: `crates/solver/src/solver.rs`;
- WASM DTO boundary: `crates/solver/src/model.rs` and `lib.rs`;
- application orchestration: `src/hooks/useSimulation.ts`;
- visual tokens and animation: `src/styles.css`.

## Verification

Before completing a change, run:

```sh
bun install
bun run check
bun run build
```

`bun run check` builds development WASM bindings, runs TypeScript, Bun tests and Rust tests. CI additionally runs rustfmt and clippy with warnings denied.

When changing only Rust logic, at minimum run:

```sh
cargo fmt --all -- --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

## Pull requests

Keep PRs vertical and demonstrable. A new component should include its domain type, ports/symbol, netlist mapping, Rust device support when required, inspector fields, tests and documentation in one change.

Do not merge generated `target/`, `dist/` or `src/wasm/pkg/` artifacts. `bun.lock` is committed once generated by Bun 1.4.
